# MLX Whisper Skill

Локальное распознавание речи на Apple Silicon через mlx-whisper. Модель выбирается
автоматически по языку: русский — специализированная whisper-podlodka-turbo q8, все
остальные — мультиязычная whisper-large-v3-turbo-8bit. Загрузка → распознавание →
выгрузка: модель занимает RAM только на время процесса mlx_whisper (~1.85 ГБ пик),
демонов и резидентных процессов нет.

## Environment

- CLI: `mlx_whisper` (uv tool `mlx-whisper`, окружение изолировано, обновление: `uv tool upgrade mlx-whisper`)
- Модели — выбор АВТОМАТИЧЕСКИЙ по `--language` (оба скрипта), явный `--model` перекрывает:
  - **ru → whisper-podlodka-turbo q8 (8 бит)** локально в
    `~/.local/share/models/whisper-podlodka-turbo-MLX-q8/` (config.json + weights.safetensors, 824 МБ).
    Источник: evilfreelancer/whisper-podlodka-turbo-MLX (q8/), база bond005/whisper-podlodka-turbo.
    q8 быстрее fp16 при совпадении текста 99.8%. fp16 лежит рядом в
    `~/.local/share/models/whisper-podlodka-turbo-MLX-fp16/` — передать путь явно через `--model`
    (сырой CLI) / аргумент модели скриптов.
  - **все остальные языки → whisper-large-v3-turbo-8bit** локально в
    `~/.local/share/models/whisper-large-v3-turbo-8bit/` (config.json + weights.safetensors, ~809 МБ).
    Источник: mlx-community/whisper-large-v3-turbo-8bit (файл model.safetensors сохранён как
    weights.safetensors — такого имени ждёт mlx_whisper).
- Тянет ffmpeg для декодирования не-wav аудио; wav 24k mono берёт как есть
- Тест-эталон: 15.7 c русская речь → чистый текст за 4.6 c (RAM 1.85 ГБ)

## When to Use

- «распознай/транскрибируй аудио/голосовое/запись» — любой локальный файл (wav/mp3/m4a/mp4/ogg)
- речь на любом языке (ru — podlodka q8, остальные — large-v3-turbo-8bit); длинные записи; нужны субтитры srt/vtt или таймстампы
- Don't use for: диаризация спикеров (кто говорил), живые стримы

## Quick Reference

**Основной путь — пайплайн VAD+STT+коррекция (скрипт `vad_transcribe.py`), ДВА ВЫЗОВА:**

```bash
# 1) транскрибация: VAD → STT → regex-препасс → MD + payload для коррекции
~/.local/share/uv/tools/mlx-whisper/bin/python \
  ~/.hermes/skills/media/mlx-whisper/scripts/vad_transcribe.py <аудио> [ещё...] --language ru
# результат: ~/result-mlx-whisper/YYYY-MM-DD_<имя-аудио>.md
#   + рядом <имя>.correct-payload.json (только когда есть канон-термины или субтитры)
#   и строка PAYLOAD <путь> в выводе

# 2) коррекция: ОСНОВНАЯ МОДЕЛЬ (ты) читаешь готовый MD + файл субтитров (если был) —
#    описание и термины уже в твоём контексте (метаданные источника) — и пишешь СПИСОК
#    ЗАМЕН в <имя>.edits.json рядом с payload:
#      [{"old": "текст как в MD", "new": "исправлено"}, {"old": "...", "new": "...", "all": true}]
#    old копируется посимвольно из MD БЕЗ таймкодов **mm:ss** и не пересекает границу блока;
#    "all": true — заменить все вхождения (иначе >1 вхождения = пропуск как неоднозначной).
#    Править только ослышки и написание терминов; поток слов, пунктуацию и грамматику не
#    трогать; числа — всегда из транскрипта (числовой гейт иначе отклонит).
#    Префлайт (пропуски с причинами + вердикт гейтов ДО apply; exit 1 = REJECT):
~/.local/share/uv/tools/mlx-whisper/bin/python \
  ~/.hermes/skills/media/mlx-whisper/scripts/vad_transcribe.py \
  --check-edits <имя>.correct-payload.json <имя>.edits.json
~/.local/share/uv/tools/mlx-whisper/bin/python \
  ~/.hermes/skills/media/mlx-whisper/scripts/vad_transcribe.py \
  --apply-edits <имя>.correct-payload.json <имя>.edits.json
# exit 0 → MD переписан с правками + <имя>.corrections.md (принятые + пропущенные с причинами);
# exit 1 → вывод отклонён, MD на базе, причина в строке REJECTED с цифрами
# (баланс слов / сумма вставок-удалений / бюджет / рывок).
# Легаси-режим полного текста: --apply-corrections PAYLOAD CORRECTED_TXT — без изменений.
```

Этапы: Silero VAD (паузы/эффекты отрезаются) → нарезка ≤28 с → mlx_whisper.transcribe() в одном
процессе (`condition_on_previous_text=False`) → regex-препасс по словарю mishear →
MD на диск + payload для судьи (payload — данные для гейтов и пересборки MD; советчик его
НЕ читает). Коррекцию выполняет ОСНОВНАЯ МОДЕЛЬ агента (советчик): она читает готовый MD и
субтитры и отдаёт список замен — вывод в 10+ раз короче полного переписывания транскрипта.
Принятие правок решает детерминированный код (судья) — гейты в `--apply-edits` (см. ниже).

**Формат MD-результата:** транскрипт = блоки ~60 с. Новый блок начинается на предложении, старт
которого БЛИЖЕ всего к «старт предыдущего блока + 60 с» (детерминированный `group_into_blocks`,
без модели: сравнение |старт − target| текущей и следующей границы). Каждый блок — одна строка
`**mm:ss** текст` + ПУСТАЯ СТРОКА после (всегда, без исключений). Хвост <20 с вливается
в предыдущий блок (если результат ≤80 с). Коротких блоков нет по построению; единственный случай
блока >60 с — предложение длиннее 60 с (по правилу «заканчивается ближайшее предложение»).

- `--no-correct` — пропустить подготовку коррекции (без payload, regex-only текст);
  `--terms` — добавить канонические написания сверх словаря.
- `--meta-title/--meta-author/--meta-date/--meta-url` — контент-метаданные для шапки MD
  (название видео, автор, дата публикации YYYY-MM-DD, каноническая ссылка без t=/si-параметров).
  Блок идёт в шапке ПЕРВЫМ, перед техническими строками, и отделяется от них пустой строкой;
  строка «Название» пишется всегда (без `--meta-title` — имя файла с расширением), остальные —
  только когда значение передано.
- **ГЕЙТ — пустые метаданные запрещены**: каждый `--meta-*` либо не передаётся, либо несёт
  непустое значение (vad_transcribe.py падает с ошибкой на пустой строке). Если метаданные
  частично или полностью определить нельзя (передан готовый файл или источник из интернета их
  не содержит) — ЗАПРОСИТЬ недостающие у пользователя, предложив вариант по умолчанию для
  отсутствующих значений: название — имя файла с расширением; автор — unknown; дата
  публикации — предложить текущую дату; ссылка — переданная пользователем или найденная
  ссылка интернет, для файла — полный относительный путь к файлу. Записывать пустые значения
  или не спрашивать пользователя ЗАПРЕЩЕНО.
- `--subs <srt/vtt>` — субтитры как ВТОРОЕ МНЕНИЕ для коррекции (не референс — см. гейты ниже).
  Дополнительно из субтитров авто-извлекаются канон-термины (имена собственные с mid-sentence
  капитализацией; фильтры: пропуск слов, встречающихся lowercase в сабах, капитализированных
  только в начале предложений, обрывков multiword брендов, вариантов уже правильных терминов) —
  печатаются как «авто-термины из субтитров». Использование субтитров фиксируется в шапке MD
  (строка «Субтитры»).
- **Коррекция = список замен, а не переписывание транскрипта**: основная модель читает
  готовый MD + субтитры (описание и термины — из метаданных источника в её контексте) и
  пишет `<имя>.edits.json`: `[{"old", "new"}]`, `"all": true` для замены всех вхождений.
  `old` копируется посимвольно из MD без таймкодов `**mm:ss**` и не пересекает границу
  блока (нужно исправить текст через блок — две отдельные замены). Замены применяются к
  словопотоку с нормализацией пробелов; правки терминов охватывают ВСЕ регистровые
  варианты написания (omlx/OMLX/Omelix — регистронезависимо к канонической форме).
- **Архитектура «советчик + судья»**: советчик (основная модель) периодически нарушает правила
  инструкций — принятие вывода решает только детерминированный код `--apply-edits` /
  `--apply-corrections`, ДВА гейта: (а) word-diff бюджет —
  пословный difflib входа/вывода: замены любого размера + вставки/удаления ≤25 слов суммарно
  (бюджет = max(2, min(25, слова//100)) — растёт с длиной транскрипта: легальные слияния
  «два слова → дефисный компаунд» масштабируются с объёмом)
  и ≤3 за один рывок, больше — весь вывод отклоняется (regex-only, exit 1). Точное равенство числа
  слов НЕ требовать — слишком жёстко, режет легальные замены типа «V four point five → V 4.5».
  (б) числовой гейт — для каждой правки сравниваются digit-токены обеих сторон (`$3.12`→`3.12`);
  отличаются — правка откатывается ПОЗИЦИОННО (вывод пересобирается из difflib-опкодов, базовые
  слова подставляются на место правки), лог «ОТКЛОНЕНО: числа» в `.corrections.md`. Хорошие
  числовые конверсии тоже отклоняются — осознанный консерватизм. В режиме edits числовой
  отказ виден сразу по каждой замене, ещё до гейтов (раздел «Пропущенные замены»).
- Правила коррекции для советчика (выполняет основная модель по MD и субтитрам): «два
  неточных машинных транскрипта» — транскрипт Whisper (словопоток авторитетен, по числам
  приоритет всегда у него) + субтитры как ВТОРОЕ МНЕНИЕ (не референс: у auto-captions свои
  системные ошибки — слитные числа, пропущенные слова); расхождения решаются своими
  знаниями (термины, бренды, версии) + клауза «при сомнении оставляй базу». Править только
  явные ослышки и написание терминов; не перефразировать, не править пунктуацию и
  грамматику, не конвертировать числа между словами и цифрами.
- Быстрый MD без коррекции и VAD: `python3 ~/.hermes/skills/media/mlx-whisper/scripts/transcribe_to_md.py <аудио>`
- Основной MD-файл: шапка = блок контент-метаданных (название, автор, дата публикации, ссылка —
  всегда, см. `--meta-*` выше) + пустая строка + технические метаданные (дата, источник, субтитры,
  длительность, модель, коррекция терминов, время этапов); далее транскрипт блоками `**mm:ss**`.
  MD быстрого пути (`transcribe_to_md.py`) дополнительно содержит таблицу сегментов.

**Сырой mlx_whisper** (когда MD не нужен — srt, перевод, отладка). Путь модели выбрать по
языку: ru → `~/.local/share/models/whisper-podlodka-turbo-MLX-q8`, остальные →
`~/.local/share/models/whisper-large-v3-turbo-8bit`:

```bash
# субтитры + таймстампы слов (пример для ru)
mlx_whisper --model ~/.local/share/models/whisper-podlodka-turbo-MLX-q8 \
  --language ru --condition-on-previous-text False \
  --output-format srt --word-timestamps True --output-dir /tmp/stt <аудио>

# форматы вывода: txt, vtt, srt, tsv, json, all (json содержит сегменты с вероятностями)
# перевод ru→en: --task translate (обратно en→ru НЕ умеет)
# фрагмент файла: --clip-timestamps "30"  (формат mm:ss CLI НЕ понимает — только секунды)
# промпт-контекст для имён/терминов: --initial-prompt "..." (термины НЕ исправляет, только стиль)
```

## Машинное потребление другими скиллами

Скиллы `multilingual-audio-replacement` и `translated-video-subtitles` используют этот
STT-стек как общий. Стабильные контракты:

- **Сегменты JSON (для пайплайнов):** `vad_transcribe.py <аудио> --language <code>
  --no-correct --debug-segments` → рядом с MD пишется
  `~/result-mlx-whisper/YYYY-MM-DD_<имя>.segments.json`:
  `{"file": ..., "segments": [{"start", "end", "text", "logprob"}, ...]}` — сегменты
  VAD-пайплайна с таймингами в секундах и avg_logprob Whisper. Путь не настраивается.
- **Word timestamps:** vad_transcribe их не пишет; нужны пословные тайминги — сырой
  mlx_whisper с `--word-timestamps True --output-format json` (см. Quick Reference).
- **VAD — фильтр «речь vs не-речь», а не анти-шум**: Silero отбрасывает пение и
  неречевые звуки (замер: 59 с песни → 0 интервалов). Следствия:
  - проверочные транскрибации («стем пуст», «в финале не осталось исходной речи»,
    аудиореференс 3–10 с для клонирования) делать ТОЛЬКО сырым CLI — через
    vad_transcribe проверка пустоты проходит вакуумно, а из короткого сэмпла VAD
    может молча уронить тихую речь;
  - чистая песня на входе vad_transcribe → 0 сегментов — корректный результат
    «речи нет», а не сбой.
- **Точность таймингов VAD-пути**: старты сегментов/предложений запаздывают против
  пословных таймингов в медиане на ~0.2 с, максимум до ~0.6 с (замер на en-речи).
  Для монтажных нарезок по этим таймингам брать padding 0.2–0.25 с, а не 0.1 с.

## Procedure

1. Определить, что скачиваем (видео/mp3/плейлист/субтитры). Основной путь — скрипт `vad_transcribe.py`
   (VAD → STT → подготовка коррекции, датированный MD в `~/result-mlx-whisper/`).
2. Запустить: `~/.local/share/uv/tools/mlx-whisper/bin/python ~/.hermes/skills/media/mlx-whisper/scripts/vad_transcribe.py <аудио> --language ru`;
   для длинных файлов — `terminal(background=true, notify_on_complete=true)` + `process wait`.
   Без `notify_on_complete=true` процесс завершится молча, а окно `wait` зажимается до 180 с —
   длинную транскрипцию придётся опрашивать несколькими заходами. Скрипт печатает прогресс по этапам и `OK <путь>`.
3. **Коррекция (шаг обязателен, когда напечатана строка `PAYLOAD <путь>`)**: прочитать
   готовый MD (`read_file`) + файл субтитров (если передавался `--subs`); описание и
   термины — из контекста (метаданные источника). Записать список замен в `<имя>.edits.json`
   рядом с payload: `[{"old": "...", "new": "..."}]`, `"all": true` для замены всех
   вхождений; `old` — посимвольно из MD, без таймкодов, не через границу блока. Затем
   ПРЕФЛАЙТ `--check-edits <payload> <edits.json>` (пропуски с причинами + вердикт гейтов
   до записи; exit 1 = REJECT) — отказ чинится по цифрам из сообщения, а не перебором
   вслепую; при OK запускать `--apply-edits <payload> <edits.json>`. exit 0 — MD переписан,
   правки и пропуски в `<имя>.corrections.md`; exit 1 — вывод отклонён гейтами, MD остался
   на базе (разобрать причину по REJECTED и переписать точнее). Пропущенные замены
   (неоднозначный/ненайденный `old`) — не ошибка: при желании добить их вторым списком
   поверх обновлённого MD тем же `--apply-edits`. Без строки PAYLOAD — коррекция не
   требовалась, MD уже финальный.
4. Прочитать созданный MD (`read_file`), показать пользователю текст и список правок.
4. **ГЕЙТ — определить язык ДО запуска, иначе не запускать вообще** (запуск с чужим языком —
   полная потеря работы и полный перезапуск). Порядок:
   а. Взять язык из самого источника: заголовок/описание (для YouTube — `yt-dlp --print "%(title)s | %(description)s"` — доступно ДО скачивания), метаданные, субтитры.
   б. Если источник неинформативен — прогнать детект на первых 30 с сырым mlx_whisper БЕЗ `--language` (или short-фрагмент) и прочитать `language` из результата.
   в. Перед запуском полного файла убедиться: в команде стоит явный `--language <detected>` и ты можешь назвать, ИЗ КАКОГО ИСТОЧНИКА взят этот язык («так в заголовке», «детект на 30 с дал en»). Не можешь назвать источник — стоп, гейт не пройден.
   г. Язык из памяти о прошлых задачах / привычки / дефолта («обычно всё русское») — ЗАПРЕЩЁН как источник.
5. Нужен srt/перевод/фрагмент — сырой mlx_whisper из Quick Reference (не забывать `--condition-on-previous-text False`).

## Pitfalls

- **Путь модели — папка, не HF-id**: с локальной папкой работает офлайн и без сюрпризов кэша HF.
- **Модель выбирается по `--language` автоматически**: ru → podlodka q8, всё остальное →
  whisper-large-v3-turbo-8bit; `--model <папка>` перекрывает выбор. Для не-ru языка папка
  `~/.local/share/models/whisper-large-v3-turbo-8bit/` обязана существовать — иначе скрипт
  упадёт на старте с понятной ошибкой (podlodka для не-ru не годится: она ru-специализирована).
- `--language ru` указывать явно: без него Whisper детектит язык сам и на коротких клипах иногда ошибается.
- Галлюцинации на тишине/музыке: повторяющиеся фразы = признак. Лечится `--condition-on-previous-text False`:
  в скриптах скилла включено всегда; в сырых вызовах передавать руками — убирает петли-повторы
  и восстанавливает фразы, потерянные после музыкальных вставок.
- VAD-пайплайн требует: venv `~/.local/share/stt-vad/` (onnxruntime+numpy), Silero onnx
  `~/.local/share/models/silero-vad/silero_vad.onnx`, ffmpeg. Запускать именно uv-tool питоном
  (`~/.local/share/uv/tools/mlx-whisper/bin/python`) — там mlx. Без шага коррекции
  (нет payload или вывод отклонён гейтами) в MD остаётся regex-only текст — это честная
  деградация, статус всегда зафиксирован в строке «Коррекция терминов» шапки MD.
- **Модель недетерминирована — не судить о промпте по одному прогону**: один и тот же вход
  даёт то чистый результат, то попытки порчи чисел/вставок; пограничные кейсы флипаются между
  запусками. Промпт сдвигает распределение, гарантию дают только кодовые гейты. Сравнение
  конфигов/моделей — на идентичном входе и с разбором списка правок, не по счётчику.
- initial-prompt НЕ исправляет термины и даёт регрессы — только для стиля; орфографию терминов
  чинит этап коррекции по канон-списку.
- `--fp16` флаг CLI не трогать: он про float16 при декодировании в оригинальном whisper, не про формат весов.
- Русские таймстампы srt сдвигаются на паузах — для точного монтажа включать `--word-timestamps True`.
- **Whisper пишет составные числительные одним числом**: сказанное «тысяч четыреста»
  становится в транскрипте `1400`, «двести пятьдесят тысяч» → `250000`. Числовой гейт
  коррекции это не чинит (числа — всегда из Whisper и не меняются), поэтому при чтении
  транскрипта и пересказе трактовать такие числа по контексту фразы, а не буквально:
  «200к достаточно, но было бы неплохо 1400» — это 400 тысяч, а не «1,4 тысячи тысяч».
- Если нужен другой квант (q4 — меньше RAM, fp16 — чуть точнее): скачать соотв. папку из того же HF-репо рядом и передать её путь.
